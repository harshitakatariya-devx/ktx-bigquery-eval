# ktx on BigQuery: evaluation

A proof of concept that tests [ktx](https://github.com/Kaelio/ktx) (an
open-source context layer for data agents) on our BigQuery warehouse
(`sahil-devx.dev_dna_silver`).

**Questions it answers:** does ktx really build a semantic layer from the
warehouse, does an AI agent using it give **correct** answers, and what does
it **cost**?

This folder is itself the ktx project: ktx reads `ktx.yaml`, writes
`semantic-layer/` and `wiki/`, and commits its own changes to this git repo.
Nothing is ever written to BigQuery (read-only service account, 10 GB cap per
query).

## Results (silver, October 2026)

| Question | Answer |
|---|---|
| Does ktx build a semantic layer by itself? | **Partly.** From the schema alone it built 23 sources, 317 described columns and **25 joins, all verified correct**, and it correctly rejected 2 trap joins. It created **0 business metrics** (by design) and missed 3 multi-table links. |
| Are the answers correct? | **13 / 15** on the team's benchmark: the same as the Snowflake semantic view (13 / 15) and above Snowflake descriptions-only (9.5 / 15). Every answer that used a defined metric was exact; both misses had no metric defined. |
| Does a semantic layer help? | **Yes.** Before metrics existed, Claude's revenue matched the official rule on 2 of 6 channels; after, 6 of 6, in 25 s instead of 66 s. |
| Can ktx's self-learning be trusted? | **Not without review.** 7 of 10 things it wrote were right; one metric it committed was wrong (1,050 active employees instead of 641, now fixed). |
| What does it cost? | **No extra bill.** ktx is free, Claude runs on the existing subscription, and BigQuery use (a few GB) is inside the 1 TiB/month free tier. See [docs/COSTS.md](docs/COSTS.md). |

## How it works

```
 BUILD (on setup / re-scan)                         ANSWER (every question)

 BigQuery schema + sample rows                      You ──► Claude Code
        │                                                     │ MCP tools
        ▼                                                     ▼
 ktx scan ─► LLM descriptions ─► join detection     ktx MCP server (localhost:7878)
        │                                             discover_data ─► search index
        ▼                                             sl_query      ─► ktx writes the SQL
 semantic-layer/*.yaml + wiki/*.md (files in git)                      from the YAML
        │                                                     │
        └─► .ktx/db.sqlite (search index, local)              ▼
                                                      BigQuery (read-only)
```

ktx does not generate business metrics (revenue, units, discounts…). We wrote
them as overlay files next to ktx's generated `_schema` file, so a re-scan
never overwrites them.

## Repo layout

```
ktx.yaml                       ktx config: BigQuery connection, 23 tables, LLM models, cost cap
semantic-layer/warehouse/
  _schema/dev_dna_silver.yaml  generated by ktx: tables, columns, descriptions, joins
  <table>.yaml                 overlays: metrics we wrote (dim_customer, employees written by ktx)
  sales.yaml                   all 6 sales channels in one source, with the revenue metrics
wiki/global/*.md               business notes ktx wrote during conversations (self-learning)
raw-sources/                   evidence from ktx's scans (schema, sample values, join profiling)
.ktx/                          ktx state; only config is in git, the index is rebuilt locally
.claude/                       Claude Code: ktx skill + rule that blocks reading eval/
.mcp.json                      tells Claude Code where the ktx MCP server is
docs/                          explanations, audit, costs, open questions, build log
eval/                          benchmark: questions, ground-truth SQL, runs, audit evidence
```

The data is synthetic test data; `raw-sources/` and `eval/` contain sample
values from it (for example `@example.com` emails). Keep the repo private.
